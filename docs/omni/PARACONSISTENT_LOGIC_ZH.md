# 矛盾容忍逻辑：完整导论

**简体中文** · ZXV — 矛盾容忍逻辑 · 状态机 · 结算


每个分布式系统最终都会面对同一堵墙：两个信息源对真相产生冲突，系统必须决定怎么办。经典二值逻辑在矛盾证据到达时会触发爆炸原理——从矛盾可推出任何命题，因此什么都不可靠。矛盾容忍逻辑给出不同的答案：把矛盾本身当作信息。

---

## 1. 经典逻辑无法解决的问题
排中律（P 或非P）假设每个命题非真即假。但在分布式环境中，网络分区和复制延迟意味着 P 与非P 可能同时到达。经典系统以恐慌、最后写入优先、死锁或多数决回应——每一种都丢失信息。

---

## 2. 四个值
四值状态机把 TRUE、FALSE、NEITHER、BOTH 作为第一等状态。BOTH 表示矛盾被记录并保持——绝不强制、绝不抹除。这是贝尔纳普四值逻辑作为系统原语的改造。

---

## 3. 链上 meet 代数
把状态排成全序：FALSE < NEITHER < BOTH < TRUE。meet（合取）返回较小秩，join（析取）返回较大秩。因为 TRUE 在顶端，非 TRUE 值组合永远无法产生 TRUE——不变式是结构性的，不是检查出来的。

---

## 4. 不变式
结算规则从秩结构自然导出：唯有真可结算。矛盾（BOTH）被保持并记入日志；只有合意（TRUE）授权行动。代数满足幂等、交换、结合、吸收——一个在全部 16 与 64 种组合上验证的有界格。

**唯有真可结算。真＋伪＝真伪两值——矛盾被记录，绝不强制，绝不恐慌。**

---

## 5. 结论
矛盾容忍逻辑解决了经典系统拒绝面对的问题：真相被争议时怎么办。答案是保存矛盾作为证据、记入日志、只在真正的合意上结算。
